# Vivo Offline Agent | Deep research plan (2026-11-22)

## Decision
Start with an adapter-based architecture: native Jetpack Compose chat, optional AI Elements UI, local llama.cpp in Termux, explicit per-action approval gate, and Koog only after comparison with current Python agent loop.

## Evidence
- AI Elements Kotlin: https://github.com/JuneLeGency/ai-elements-kotlin ; README shows BOM 0.3.0; chat stream, Markdown, tool approvals, MCP/AG-UI, optional in-app agent. Alpha Compose/Material 3 dependencies may affect build stability.
- Koog: https://github.com/JetBrains/koog ; https://docs.koog.ai/llm-providers/ ; Android supported, Ollama local supported. **Not yet verified:** exact integration with llama.cpp OpenAI endpoint and compatibility with chosen 9B GGUF.
- llama.cpp: https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md ; OpenAI-compatible HTTP chat interface. Tool calls depend on compatible model/chat template.
- Termux: https://github.com/termux/termux-app/wiki/RUN_COMMAND-Intent ; external app requires explicit RUN_COMMAND permission. Never execute arbitrary commands generated by model without user approval.

## Architecture
Android UI (Compose / AI Elements) -> ChatBackend interface -> local broker -> Termux llama.cpp. Agent orchestration: current Termux Python by default, optional Koog as test branch. Tools: typed requests -> policy -> explicit approval -> controlled Termux / file / SSH / Shizuku adapter -> audit trail. Cloud inference disabled unless manually enabled.

## Definition of done
Buildable proof-of-concept, verified API connection, offline chat in Persian/English, no unattended shell command execution, repeatable benchmarks and documented decision matrix.

## Status
Research outline prepared; implementation and compatibility testing **not yet performed**.
